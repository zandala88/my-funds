# 柔和原生界面与支付宝截图导入

用户本轮明确要求：美化方正的 UI，删除独立行情模块，增加图片 OCR 持仓识别；截图来自支付宝。继续在 my-funds 的现有开发分支实现。

## 已决定的行为

- 导航仅保留自选和设置，移除指数、板块和行情中心入口及其请求。基金自己的净值、详情和收益功能保留；旧备份中的指数设置仍可读取以保持文件兼容。
- 界面保持原生组件，使用柔和中性背景、28dp 卡片、胶囊按钮/导航、较少边框、明确的金额排版和留白。替换平台方形按钮外观，不引入大型界面库或字体。
- 截图只在本机读取。采用 Tesseract4Android 4.9.0 和 tessdata_fast 4.1.0 简体中文模型；不使用云 OCR、账号或按次付费服务，也不引入会产生运行统计联网的 OCR SDK。模型内置，首次识别无需下载或 Google 服务。
- 安装包会因引擎和中文模型增大；提供通用 APK 与按 ABI 的较小 APK，最终记录实际大小，不继续承诺 80KB。

## 识别流程

自选页“截图导入” → 系统选择一张图片 → 本机缩放及 OCR → 结构化待确认条目 → 编辑/基金匹配 → 用户明确选中并保存。

- 图片大小与像素有上限；缩放避免长截图导致内存耗尽。识别在后台执行，可取消；页面销毁后丢弃结果，释放 Bitmap 和引擎。图片不复制到持久存储、不进入日志或备份。
- 按文本行和位置解析支付宝持仓列表/详情，提取基金名称、完整代码、金额、收益、份额、成本及确认日期。没有标签对应的数字不得随意归为份额或成本；账户总额/昨日收益等汇总不作为单只基金导入。
- 列表常常没有份额及成本，因此金额和收益只作核对参考，不按最新净值反推份额或成本。缺项以待补齐展示。
- 完整六位基金代码优先；没有代码时，只有用户点击匹配才联网搜索名称。A/C/E 等份额类别、截断名称和多个候选必须由用户选择，不自动猜基金。
- 每条记录均允许修改名称/代码/已确认份额/平均成本/确认日期，默认不自动选中写入。必须代码有效且份额成本齐全，才能保存为持仓；仅名称/代码可明确选为“只加自选”。
- 新基金在当前分组建立起始快照；已有基金默认不修改。用户明确选择更新已有持仓时保存校准记录，不重复累加份额、不伪造买卖、不中断已有账本；确认日期不得早于已有记录。一次确认事务保存全部选择，先校验后提交；同一次导入内重复代码拒绝。
- 单次先支持一张截图，页面支持编辑识别文本后重新解析，以便 OCR 有遗漏时修正。没有真实支付宝样例时只声称通用适配，不能声称已覆盖所有支付宝版本。

## 验证与交付

- 纯 Kotlin 测试覆盖支付宝标签、完整/截断名称、A/C 区分、列表金额不是份额、总额不入库、重复代码、缺项/非法数值、已有基金不被静默覆盖及取消无副作用。
- 使用生成的中文测试图片在本机 Tesseract 上验证模型可运行及文本提取；这不替代安卓 JNI 真机测试或真实支付宝截图验证。
- 保留原版本备份兼容；更新 versionCode/versionName；使用现有签名产出新 APK，记录测试、Lint、签名、权限和大小。
- 用户给定方向已明确，样式和本机引擎为实现方的常规选择，直接推进；真实截图可在后续校准解析，不阻塞独立的 UI 和模块移除。

## 实施和审阅补充

实际实现中进一步要求：完整数字格式与字段标签一一对应，不能截断多个小数点；只取总持有份额，不把可用份额当总额；确认日期无明确来源时留空，提供用户主动点“今天”或批量填空项；核对表和部分输入以有界草稿恢复；无变化导入不覆盖恢复点；发起导入的分组随主界面状态保存。

ARM64 包约 4.8MiB，通用约 14MiB。构建、Lint 和核心回归已通过；未进行实际安卓设备测试，也没有用户真实支付宝截图。
