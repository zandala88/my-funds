# 自用轻量原生安卓基金应用设计

日期：2026-11-24。状态：已在 my-funds 实现本机原生版本，完成核心测试及 APK 构建；真机交互验证待进行。

## 已确定的需求

- 仅供用户本人在安卓手机使用，采用原生安卓实现，可以重新编写代码。
- 功能以 x2rr/funds 为参照，优先控制安装包、内存、耗电和依赖数量。
- 自选、持仓和设置保存在本机；联网仅用于获取行情及其配套基金资料。
- 不需要账号同步、服务器推送、付费数据源、自建服务器或域名。
- 支持导出数据文件，在另一部手机导入并恢复。

## 方案取舍

之前比较了原生安卓和网页加 WebView 两条路线。网页方案可以更快复用界面，但依赖 WebView；原生方案需要重写界面，便于控制运行资源。用户已选择原生安卓。

以下技术细节和默认行为为实现方提案，用户可在本设计审阅时修改：Kotlin、Android 系统 View、轻量原生折线图、系统 SQLite、本机文件备份。避免为了简单功能引入大型 UI、图表和跨平台运行时。最低系统版本暂定 Android 8.0（API 26），工作名称“基金自选”。依赖版本在实施计划中根据官方兼容要求确定。

## 功能与交付边界

分批实现以下功能，不把第一批作为全部功能已经完成的依据：

1. 核心闭环：按名称/代码搜索、添加删除自选、录入份额及成本、查看已公布净值及日期、持仓金额和收益、手动刷新、完整备份与恢复。
2. 持仓使用：分组、自定义顺序和排序、汇总、加仓减仓记录、明暗主题、显示项设置。
3. 基金详情：历史净值及收益曲线、基金概况、经理信息、披露的股票持仓；每项仅在进入详情时加载。
4. 行情补齐：自选大盘指数、走势及原项目行情中心可获取的数据。盘中估值和估值曲线从第一批开始验证，能获得有效数据即展示；接口不可用时明确显示暂无估值，不能伪造或替换成零涨跌。历史北向资金等可能停更的数据必须带数据日期，不能当成实时行情。

浏览器角标和右键菜单转换为应用内关注、排序和显示设置，不照搬浏览器交互。README 提到的截图识别导入属于作者另一个小程序，当前仓库未提供相应实现，不纳入本次本机版。

## 数据流与运行行为

原生界面 → 本机仓库 → SQLite；行情仓库 → 可替换的数据源适配器 → 东方财富/天天基金 HTTPS 接口。

- 持仓、分组、交易和设置在本地读写，自动保存，不要求登录。
- 行情请求仅传查询所需的基金/证券代码和接口要求的非敏感参数，不上传份额、成本、交易记录或备份。
- 原仓库搜索使用 fundsuggest.eastmoney.com；净值、估值、走势、经理和持仓资料使用 fundmobapi.eastmoney.com；证券行情使用 push2.eastmoney.com。所有接口均需逐项验证业务状态和字段，不能只检查 HTTP 200。
- 不依赖作者账号服务，也不把作者 GitHub 更新日志或节假日文件作为后台自动联网依赖。
- 首屏先展示本机缓存，再请求新数据；无网络仍可查看持仓和缓存，并显示数据时间。
- 用户手动刷新始终可用。前台自动刷新默认关闭，可开启约 60 秒间隔；退到后台、锁屏或页面不可见即停止。避免同一请求并发重复，失败采用退避而非持续重试。
- 日历只辅助控制刷新，行情日期及估值时间为显示依据；不能仅依照普通工作日判断交易所开市。首版不承诺自动判断所有交易所节假日。
- 每类资料独立处理缺失、超时和接口失效，保留最后一次成功数据，显示来源、时间及是否为估算。
- 前面的接口抽测只证明搜索和历史净值曾返回数据；估值字段缺失及业务报错已经出现。盘中实时估值是数据源验证项，不作为已经验证可用的能力。

## 持仓与金额

- 金额、份额、成本和净值以十进制定点语义计算（BigDecimal），持久化和备份使用十进制字符串，展示金额四舍五入到两位；基金代码始终为字符串，保留前导零。
- 核心闭环允许直接录入已确认份额和平均单位成本。加减仓采用用户输入的已确认份额、成交净值和手续费，保留操作日期与记录；不连接交易账户、不自动申赎。
- 加仓按已有成本金额加新增支出及手续费计算平均单位成本；减仓扣减份额，剩余平均成本保持不变，单独记录扣费后的已实现收益。禁止份额为负或卖出超过持有份额。
- 持有收益以已公布净值计算，估算当日收益单独展示；持有收益、已实现收益与两者合计分别命名。已实现收益明确标注“建账以来”，不暗示覆盖初始快照之前的完整历史。日期、净值或估值不足时显示暂无数据，不显示误导性数值。
- 单笔初始持仓仅记录快照，创建后的操作形成交易账本；不凭空补造快照之前的交易和历史盈亏。分红和份额折算可通过明确标记的持仓校准记录处理，不能作为普通盈利买卖推算。

## 换机备份与恢复

- 通过安卓系统文件选择器导出/打开文件，不需要申请整个存储空间的访问权限。
- 导出单个 UTF-8 JSON 文件，例如 funds-backup-2026-11-24.json。文件包含格式标识、schemaVersion、导出时间、自选、分组与顺序、份额成本、交易/校准记录和显示设置。
- 备份不包含安装签名、设备标识或仅供重新下载的图表缓存。先在内存读取一致快照，再写文件；写入或关闭失败时不能提示成功。
- 导入采用“恢复此备份，替换本机数据”，不做容易重复记账的自动合并。展示备份时间与基金/记录数量，用户确认后才替换。
- 全量校验格式、版本、大小上限、基金代码、十进制数值、ID 唯一性及分组/交易引用；验证完成后再通过数据库事务原子写入，任一错误均保留原数据。
- 提交导入前先在应用私有空间保存一份现有数据恢复点；失败时不得继续覆盖。恢复点只在本机，不需要服务器。
- 同一备份反复导入应恢复同一份数据，不增加重复记录。未知未来版本拒绝导入，并给出明确原因。
- 文件为明文备份，界面明确说明保存内容；首版不引入密码、密钥恢复和加密文件兼容机制。

## 轻量与隐私约束

- 正式 APK 以 10MB 以内为初步优化目标，最终提供实测结果，不将预估当成已交付指标。
- 使用系统字体及少量矢量资源；简单图表原生绘制，限制缓存并允许清理。
- 不包含广告、统计 SDK、账户 SDK、自动云备份、后台常驻服务、服务器推送或内置付费功能。应用数据明确关闭系统自动云备份，换机依赖用户导出的文件。
- 必要权限以联网为主；文件导入导出使用系统文件选择器。运行期间不要求联系人、定位或相册权限。
- 无固定服务器/域名费用。接口可访问不等于第三方长期免费服务承诺；失败时继续保留本地功能，不自动购买或切换到付费服务。

## 验收

必须验证：重启后数据仍在；离线打开能读到本机数据；备份在空库恢复后内容一致；非法/损坏/未来版本文件不覆盖现有数据；重复导入不重复记账；带前导零的代码不丢失；买卖、手续费与精度计算正确；缺失估值、旧行情、业务错误和超时不会变成零涨跌或导致空白页；退到后台后停止自动刷新。

交付包括源码、可安装的签名 APK、安装与备份说明，以及真实验证记录。签名密钥用于后续更新，单独保存在本机；不能把密钥提交到源码。模拟器验证不能代替用户手机的最终兼容性确认。
